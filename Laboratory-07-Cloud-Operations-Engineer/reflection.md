# Mission Reflection

This laboratory activity helped me understand why monitoring the host server is important even when containers appear to be running normally. Containers still depend on the resources of the host machine, such as CPU, memory, and disk space. If the host becomes overloaded or runs out of storage, the containers may slow down, stop working, or fail even if their individual configurations are correct.

If a user complains that they cannot log into a web application, the `docker logs` command can help by showing the requests and errors generated by the application. By checking the logs, I can look for failed requests, error messages, or status codes that may explain what happened during the login attempt.

I also learned the difference between logs and metrics. Logs provide detailed records of events and requests, such as HTTP 200 or 404 responses, while metrics show numerical measurements such as CPU usage, memory consumption, and network activity. Logs are useful for investigating what happened, while metrics are useful for understanding how well the system is performing.

Large enterprise companies that manage thousands of containers usually use centralized monitoring tools such as Prometheus and Grafana. These tools can collect metrics from many systems and display them in dashboards, making it easier for engineers to monitor performance and detect problems.

My ability to troubleshoot Linux environments has improved because I now know how to use commands such as `free -h`, `df -h`, `top`, `docker logs`, and `docker stats`. I am more confident in checking system resources, identifying application errors, and using both logs and metrics to understand the health of a cloud environment.
