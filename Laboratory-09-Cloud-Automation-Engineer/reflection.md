
# Mission Reflection

Completing this laboratory activity helped me understand why automation is important in cloud computing, especially when managing hundreds of servers. Instead of manually performing the same tasks repeatedly, cloud engineers can use scripts to complete them automatically. This saves time, reduces human errors, and makes managing large cloud environments more efficient.

However, I also learned that automation has potential risks. If a script contains a destructive mistake and is scheduled to run on thousands of servers, it could cause serious problems such as data loss or system failures. This is why scripts should always be reviewed and tested carefully before using them in a production environment.

Writing a Bash script was different from creating a Docker Compose YAML file in Mission 6. Bash scripting focuses on executing commands and automating tasks, while Docker Compose uses a YAML configuration file to define and manage multiple containers. Both are useful, but they serve different purposes in cloud computing.

Looking back at my laboratory activities from Mission 1 to Mission 9, I can see how much my understanding of cloud computing has improved. At first, I only had basic knowledge about cloud services and infrastructure. Throughout the semester, I learned about containers, cloud storage, deployment, monitoring, security, and automation. These activities helped me understand how different technologies work together to manage cloud environments.

Among the different cloud engineering roles, I enjoyed being a Cloud Automation Engineer the most because I found it interesting that a simple Bash script could perform tasks automatically. Creating backups and scheduling them with Cron showed me how automation can make an engineer's work easier. This mission also increased my confidence in using Linux commands and understanding real-world cloud operations.
